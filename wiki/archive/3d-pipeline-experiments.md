# 🧊 3Dパイプライン導入 実験計画（洗い出し）

3D生成（3D Gen Studio / Hunyuan3D / Rodin＋Blender）を『THE FOUR SEASONS』の制作に組み込むにあたり、**何を実験すべきか**を網羅的に列挙したノート。結論ではなく、検証すべき仮説と測定方法のカタログ。

関連: [[rules/comfyui-image-generation-reflection|画像生成 黄金ルール]] / [[rules/comfyui-mcp-workflows|ComfyUIワークフロー規定]] / [[rules/color-palettes|カラーパレット]]

---

## 0. 実験を始める前に決めるべきこと

実験の設計がここで全部変わるので、**手を動かす前に立場を決める**必要がある項目。

### 🔴 決定①：3Dは「最終画」か「中間素材」か

| 立場 | 意味 | 必要な作り込み |
| :--- | :--- | :--- |
| **A. 最終画** | Blenderのレンダー結果をそのまま作品に載せる | PBRテクスチャ、SSS、髪、クロス、ライティングまで全部本気。工数は10倍 |
| **B. 中間素材（推奨仮説）** | 3DはControlNet素材とimg2img下地を作る「治具」。最終質感は必ず2Dが乗せる | 形とシルエットとカメラだけ正しければよい。テクスチャは**灰色でも成立しうる** |

> [!important] ここが最大の分岐
> 「作り物っぽくない自然なテクスチャリング」という課題は、**立場Bを取れば大部分が消滅する**。3Dの3Dくささは img2img の denoise で溶かせるから。
> 逆に立場Aを取るなら、その先はもう画像生成の話ではなくCG制作の話になり、必要なスキルも時間軸も別物になる。
> **実験1の目的は、この2択を「感覚」ではなく「出力の比較」で決めること。**

### 🔴 決定②：どの画風に対する3Dか

本作は現状**2系統の画風**が同居している。

- **90年代16色ドット絵**（表情アイコン・スプライト）
- **セミリアル**（楓の `art_style: Photorealistic / Semi-real 3D render`）

3Dの投資対効果は後者で圧倒的に高い。ただしドット絵側でも「**正確なアタリ**」としての価値はある（等身・パース・手足の位置）。
→ **実験は楓（8.0頭身・セミリアル指定）から始めるのが最短。** 素材も一番揃っている（`kaede_body_tpose_base.jpg` / `_back_base.jpg` / `_tpose_depth.png` が既にある）。

### 🔴 決定③：4人分作るのか、1人で検証するのか

キャラ1体をパイプラインに乗せる工数が読めるまで、**楓1体に絞る**。4体展開の判断は工数実測後。

### 🟡 決定④：どこまでを再現性のある資産にするか

Blenderの手作業は再現できない＝資産にならない。`.blend` とスクリプト（`execute_blender_code` に投げた内容）をリポジトリに残す規約を最初に決めておかないと、今日の成果が明日消える。

## 1. 3Dを入れて何が得られるのか（＝実験の目的関数）

実験は「できた／できない」ではなく「**これが良くなったか**」で判定する。狙いを先に言語化しておく。

| # | 得たいもの | 現状の痛点 | 3Dでの解決仮説 |
| :--- | :--- | :--- | :--- |
| G1 | **カット間のキャラ同一性** | IP-Adapterでも角度が変わると別人化する | 同一メッシュを回すだけなので原理的にブレない |
| G2 | **任意ポーズ・任意アングル** | ポーズ参照画像を毎回探す／作る必要がある | ポーズはリグで作る。参照画像探しが消える |
| G3 | **ControlNet素材の無限供給** | canny/depth/pose を都度2D画像から抽出＝精度が参照元依存 | depth/normal/openpose/lineart を**真値**として書き出せる |
| G4 | **難所（手・足・靴・俯瞰）** | 手指の破綻、パンプスの形状崩れ、煽り／俯瞰の破綻 | 3Dなら破綻しない。ここは効果が一番わかりやすい |
| G5 | **空間の一貫性** | 会議室・教室・キャンプ場が毎回違う部屋になる | セットを1回作れば章内で使い回せる |
| G6 | **ライティング設計** | 「西日」「蛍光灯」「焚き火」が言葉頼み | HDRIとライトで意図通りに。しかも再現可能 |
| G7 | **自動マスク生成** | `generate_masks.py` で手作業に近い調整をしている | Cryptomatte / オブジェクトIDで**完全に正確なマスク**が無料で出る |
| G8 | **LoRA学習データの工場** | キャラLoRAを作りたくても教師画像が足りない | 3Dから多角度・多照明で数百枚レンダーできる |
| G9 | **濡れ・泥・染みの制御** | 位置と広がりを言葉で指示していて再現性がない | 頂点カラー／マスクテクスチャで**どこがどれだけ濡れているか**を数値で持てる |

> [!tip] G8とG7は「地味だが本命」
> 3Dの一番の勝ち筋は、たぶん**綺麗な絵を出すことではなく、2Dパイプラインの入力を工業化すること**。
> 特に **G8（LoRA用データセット生成）** は、成功すれば以後すべての2D生成の同一性問題が根本から改善する。

## 2. 実験カテゴリの洗い出し

### 🅰️ A. 素体（ベースメッシュ）の獲得ルート比較

**問い：楓の身体を、どうやって3Dにするのが一番マシか。**

| ID | ルート | 手順 | 想定される弱点 |
| :--- | :--- | :--- | :--- |
| A1 | **顔画像→頭部3D** | `kaede_face_front_base.jpg` を image-to-3D。頭部のみ | 後頭部・髪が捏造される。首から下が無い |
| A2 | **Tポーズ全身→3D一発** | `kaede_body_tpose_base.jpg` を image-to-3D | 手足が板になる／指が融合する／背面が想像で埋まる |
| A3 | **マルチビュー→3D** | 正面`_tpose_base` ＋ 背面`_tpose_back_base`（＋側面を2Dで新規生成）を multi-view 入力 | 3面の整合が取れていないと破綻。**側面画像を先に作る必要**あり |
| A4 | **パラメトリック素体＋顔移植** | VRoid / MakeHuman / Human Generator 等で素体を作り、顔だけA1で差し替えるかシェイプキーで寄せる | 生成AIらしさは無いが、**リグ済み・トポロジー綺麗・服が着せられる** |
| A5 | **ハイブリッド（本命仮説）** | 素体＝A4、顔＝A1をリファレンスにモーフ、髪と服＝別オブジェクト | 手間は最大だが唯一「運用できる」形になる可能性 |

**評価軸（毎ルート同じ表を埋める）**
- 頭身が仕様値（楓＝8.0）に合っているか／合わせられるか
- トポロジー：四角ポリゴンか、リグを入れて曲げたときに壊れないか
- 対称性・破綻箇所（指・耳・脇・股下・足首）
- 顔が「小西真奈美風の柔らかさ」「少し離れ目の子鹿」に見えるか
- 生成にかかった時間とコスト
- **UV展開があるか**（無いとテクスチャが描けない＝濡れ表現が死ぬ）

> [!warning] 生成3Dの落とし穴として先に疑うべきこと
> 画像から生成したメッシュは、たいてい **①トポロジーがぐちゃぐちゃ ②UVが自動展開で使い物にならない ③リグを入れると関節が潰れる**。
> つまり「ポーズを取らせたい」という目的には、生成3Dは**そのままでは向いていない可能性が高い**。A4/A5を最初から本命として比較対象に置くこと。

---

### 🅱️ B. プロポーション・等身の制御

**問い：仕様書の数字（head_ratio 8.0 / 7.5 / 7.0 / 6.5、身長165cm）を3Dで強制できるか。**

- B1: 生成メッシュの実測頭身を計測するスクリプト（頭頂〜顎の高さ ÷ 全長）
- B2: シェイプキー／ボーン長でのプロポーション調整、4人分のプリセット化
- B3: **4人を並べたときに差が読み取れるか**（6.5と8.0の差は成立するか）
- B4: 体型記述（「スレンダーで脚が長く」「華奢で頼りなげ」「胸・臀部に立体感」）のパラメータ化
- B5: 同一素体からの4人分岐が可能か、それとも各自別素体か

---

### 🅲 C. リグとポージング

**問い：Tポーズから、作品に必要な姿勢まで持っていけるか。**

- C1: オートリグの比較（Rigify / Mixamo / AccuRig）とデフォームの破綻検証
- C2: **作品固有のポーズライブラリ**を定義する。本作で繰り返し必要になるのは：
  - 立位・耐える（内股、太腿を擦り合わせる、片手で腹を押さえる）
  - 椅子に座って動けない（会議室・教室）
  - しゃがみ込む／膝から崩れ落ちる
  - 泥の中に手をつく（楓・第3章）
  - 顔を覆ってうつむく（既存の赤面ポーズ参照と同型）
  - 洗面台の前に立つ／振り返る
- C3: 実写／既存画像からのポーズ推定を3Dに流し込めるか（OpenPose推定→リグに転写）
- C4: 表情のリグ（シェイプキー6パターン＝ index.md の Neutral/Smile/Suspicion/Anxiety/Panic/Acceptance）
  - 特に **5. 狼狽（耳〜首の大赤面）** と **6. 虚脱（瞳から光が消える）** は3Dで作るのが難しい。テクスチャ／2D側の役割分担を決める実験
- C5: 手のポーズ（G4の本丸）。手だけのライブラリを作る価値があるか
- C6: ポーズをJSON/npzで保存して再利用する仕組み

---

### 🅳 D. 衣装

**問い：紺碧のラップワンピース・ラベンダーのレース・20〜30デニールのストッキング・ポインテッドトゥのパンプスを、どう3Dにするか。**

- D1: 衣装の作り方3ルートの比較 —— ①服も含めて丸ごと生成 ②素体に別メッシュで作る ③テクスチャで描く（服を着た状態のメッシュ）
- D2: クロスシミュレーションの要否。**濡れて張り付く**表現はシミュレーションでしか出ない可能性
- D3: **ストッキング**：半透明・光沢・伝線・膝の皺。3Dシェーダー（薄い透過レイヤー）で作れるか
- D4: **パンプス**：形状は3Dの得意分野。足首の角度と靴の整合。落ち葉の中に脱げているカット
- D5: 下着（上下セット、レース）の表現。レースはテクスチャ＋アルファで済むか
- D6: 衣装バリエーションの管理（勤務時の夜会巻き／素のロングストレートに相当する、衣装のオンオフ切り替え）
- D7: 4人分の衣装アセット化と使い回し

---

### 🅴 E. テクスチャリング（「作り物っぽくない」の追求）

**問い：どこまで作り込むと最終出力が良くなり、どこから無駄になるか（逓減点の探索）。**

- E1: 生成テクスチャのPBR分解（albedo / roughness / normal / SSS）の品質検証
- E2: 肌のサブサーフェススキャタリング。耳・鼻・指先の透け
- E3: **汗・涙・鳥肌・赤み**をどのレイヤーで持つか（テクスチャ／シェーダー／2Dのinpaint）
- E4: 髪。「濡れたような艶のある黒髪」——カード式ヘアかパーティクルか、それとも髪は2Dに任せるか
- E5: **逓減点実験**：同じポーズを「①灰色クレイレンダー ②簡易テクスチャ ③作り込みPBR」の3段階で用意し、**同じimg2img設定に通して最終出力を比較する**。
  → ②と③で最終出力に差が無いなら、**テクスチャの作り込みは全部無駄**と結論できる。これは今日やる価値が非常に高い実験。
- E6: 3Dくささの正体を分解する（対称すぎる顔／均一すぎる肌／硬い髪／完璧すぎるライティング／レンズ感の欠如）。それぞれに対する対処を個別に試す

---

### 🅵 F. 3D → 2D の橋渡し（本命の技術検証）

**問い：レンダー結果を、既存のComfyUIパイプラインにどう繋ぐか。**

- F1: **denoiseスイープ**。同一レンダーを denoise 0.20 / 0.30 / 0.40 / 0.50 / 0.60 / 0.70 で img2img し、
  「3Dくささが消える点」と「キャラ同一性が壊れる点」の間の**使える帯域**を特定する
- F2: マルチControlNetの効き方の検証（depth / normal / openpose / lineart の組み合わせと重み）
  - 既に `depth_map.json` `canny_map.json` `pose_map.json` `char_refine_dual_cn_sdxl.json` があるので接続は早い
- F3: **真値depthの効果測定**：`kaede_body_tpose_depth.png`（2D推定）と Blenderの Zパス（真値）で出力がどう違うか
- F4: **Freestyle / トゥーンシェーダーによる線画抽出** → lineart ControlNet。Cannyより綺麗な線が取れるはず
- F5: IP-Adapter（顔・画風）＋ 3D由来ControlNet（ポーズ）の併用。**黄金ルールの上位互換**になるか
- F6: **Cryptomatte → inpaintマスクの自動生成**。「ワンピースだけ」「ストッキングだけ」「顔だけ」のマスクが完璧に出る。既存の `generate_masks.py` / `inpaint_masks/` を置き換えられるか
- F7: レンダー→ComfyUI input への自動アップロード（`scripts/upload_ref.py` の流用）とMCP経由の一気通貫実行
- F8: 16色パレット化との相性（[[rules/color-palettes|季節別パレット]]への適合。3Dレンダーは階調が滑らかすぎて減色が汚くなる可能性）
- F9: 解像度と画角の規約（縦832×1216が現行既定。3D側のカメラ設定を合わせる）

### 🅶 G. 一貫性の「測定」（これが無いと実験にならない）

**問い：良くなったことを、どうやって主観以外で示すか。**

- G-1: **顔類似度スクリプト**（InsightFace/ArcFaceの埋め込みcos類似度）。基準画像 `kaede_face_front_base.jpg` に対して全生成物のスコアを出す
- G-2: 同じスクリプトを**既存の2Dワークフロー出力**にも適用し、3D経由との A/B を数値で比較する
- G-3: パレット適合度（生成画像の色ヒストグラムと `color_main` / `color_sub` の距離）
- G-4: 等身の実測（生成画像から頭部高／全身高を測る）
- G-5: 破綻検出（指の本数、四肢の数）——目視チェックリストでも可
- G-6: **同一条件・同一シードでの比較を強制する実験プロトコル**の整備

> [!important] 今日の最初の30分はここに使うべき
> 評価スクリプトが無いまま実験すると、「なんとなく良くなった気がする」で1日が終わる。
> G-1 だけでも先に作れば、以降のすべての実験が**数字で決着する**。

### 🅷 H. 3Dを「データ生成器」として使う（LoRA／IP-Adapter資産）

**問い：3Dモデルから学習データを量産して、キャラLoRAを作れるか。**

- H1: 多角度レンダー（ヨー36方向 × ピッチ3段階など）のデータセット生成
- H2: 照明バリエーション（HDRI複数）を混ぜないと**特定ライティングに焼き付く**問題の検証
- H3: 何枚必要か（30枚／100枚／300枚）と、学習時間・過学習の境界
- H4: **クレイレンダーで学習すると3DくさいLoRAになる**のではないか、という懸念の検証。
  → 対策仮説：レンダー画像を一度 img2img で2D化してから学習データにする（3D→2D→学習の2段構え）
- H5: 学習済みLoRA vs IP-Adapter vs 3D-ControlNet の**同一性スコア比較**（G-1で測る）
- H6: 表情6パターン × 4人分のスプライトを、LoRA＋3Dポーズで一気に揃えられるか
- H7: IP-Adapter用の「理想の参照画像」を3Dから作る（正面・均一光・無表情のリファレンスショット）

### 🅸 I. センシティブ表現（本作の中核テーマ）への対応

登場人物は全員成人（18／19／23／26歳）。本作は [[rules/style-guide|スタイルガイド]] にある通り**ポルノ化を明確に禁じ**、失禁を「社会的ペルソナを破壊するための物語上のツール」として扱う。3D導入はこの方針に対して**むしろ有利に働く**可能性がある。

- I1: **クラウド3D生成APIのフィルタ制約の把握**。Rodin等の外部サービスに何を投げられるか／投げるべきでないか。素体・下着状態の生成が通るかを事前に確認し、通らないなら**ローカル（ComfyUI上のHunyuan3D等）に寄せる**判断
- I2: 素体（ヌードメッシュ）はローカルで作り、外部サービスには顔・小物・背景だけ投げる、という**分業の設計**
- I3: **濡れ表現の制御を3D側に移す実験** —— 染みの位置・広がり・浸透具合をマスクテクスチャとして持てば、
  「言葉で指示して運任せ」から「数値で指定して再現可能」へ移行できる。**表現の下品化を防ぐ方向にも効く**（意図しない過剰描写が出ない）
- I4: 布の濡れによる色変化（albedoの暗化）・光沢増加（roughness低下）・張り付き（法線／シミュレーション）の3要素を分けて検証
- I5: 泥（楓・第3章）の表現。頂点カラーでの汚れマップ、ストッキングへの付着
- I6: 2D側チェックポイントの選定と、レンダー下地を与えたときの挙動差（現行 `speciosaAnime_v15` / `Counterfeit-V3.0` / SDXL系）
- I7: 「破綻の瞬間そのものより周囲の視線と沈黙」というトーン指定を、**カメラワークで実装する**実験（傍観者の目線、机の陰から、監視カメラ的俯瞰）——これは3Dが本質的に強い領域
- I8: 生成物の保管・公開範囲の線引き（リポジトリはQuartzで公開ビルドされる。素体・下着状態のアセットを `content/` 配下に置いてよいのか、`.gitignore` すべきかの規約）

> [!warning] I8 は技術より先に決めるべき
> `content/assets/characters/kaede/body/kaede_body_nude_base.jpg` が既にリポジトリにある。Quartzは `content/` を公開サイトとしてビルドするので、**publish設定と実際の公開範囲を今日確認しておく**こと。3D化すると素材点数が一気に増えるため、後回しにすると事故る。

### 🅹 J. 背景・セットと空間の一貫性

- J1: 章ごとの舞台を3Dセット化する価値の検証（会議室／西日の教室／キャンプ場／洗面台）
- J2: PolyHavenからのHDRI・マテリアル取得（MCPツールあり）と、ライティングプリセットの整備
  - 「西日」「オフィスの蛍光灯」「焚き火」「洗面所の白色灯」
- J3: セット＋キャラを同一シーンに置いたときの、**接地感・影・スケールの正しさ**（2D生成が最も苦手な部分）
- J4: 背景だけ3D、人物は2D、という部分適用の検討
- J5: カメラのレンズ・被写界深度の設計（作品のトーンに合う焦点距離を決める）
